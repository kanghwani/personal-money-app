# 유튜브 구독자 이벤트 추적

2026-09-21

## 문제

십만양품·디에디트 같은 리뷰 채널이 수시로 구독자 이벤트(댓글 추첨)를 여는데, 지금은 **발견 자체를 못 하고 있다.**
영상을 안 보면 모르고, 봐도 마감을 잊는다. 필요한 건 세 가지다: 놓치지 않고 알기, 쉽게 지원하기, 결과를 기록하기.

## 결정 (브레인스토밍에서 확정)

| 질문 | 결정 | 이유 |
|---|---|---|
| 발견 | 이벤트 자주 하는 채널 10~30개 고정 목록을 매일 스캔 | 구독 채널 전체는 OAuth·잡음, 전체 검색은 대형 이벤트 위주 |
| 스캔 소스 | **YouTube Data API 키** (OAuth 없음) | 채널 RSS를 직접 쳐보니 십만양품·디에디트·기즈모 404, ITSub 500. 채널마다 제각각이라 못 쓴다. API는 채널당 하루 1단위, 한도 1만 |
| 지원 | 반자동: 링크·조건·발췌까지 준비, 댓글은 손으로 | 자동 댓글은 계정 제재 위험 |
| 알림 | 단축어 자동화 → **미리알림** (마감 전날 "지원", 발표일 "결과") | 아침 브리핑은 안 보고 있음. 클로드 앱 예약작업은 커넥터가 안 실려 조용히 실패한 전례 |
| 결과 | 발표일 미리알림 + 손으로 한 줄 기록 | 당첨자 발표는 커뮤니티 게시글·고정 댓글이라 API·RSS 모두 못 읽음 |
| 가계부 | **인프라만** 빌린다(시트·GAS·MCP 서버·토큰). 데이터는 안 섞음 | 당첨금을 원장에 넣고 싶으면 기존 `ledger_add` 를 그때 부르면 된다. 코드 0 |

## 안 만드는 것

댓글 자동 작성, 당첨 자동 감지, 새 화면, 노션 연동, cron. 전부 "필요해지면" 추가.

## 루프

```
① 스캔   채널 목록 → YouTube API 최근 10개 → 이벤트 판정 → events 탭에 new
② 알림   단축어(매일 09:00)가 /api/events 호출 → 서버가 스캔 + new 목록 반환 + reminded 기록
         → 미리알림 2개 생성 (마감 전날 09:00 "지원", 발표일 09:00 "결과")
③ 지원   미리알림 → 링크 → 클로드 앱 "이벤트 뭐 있어"(event_list) → 조건·댓글 초안 → 손으로 댓글
④ 기록   클로드 앱 한 줄(event_log): "지원 십만양품" / "당첨 십만양품 에어프라이어" / "탈락 십만양품"
```

## 1. 스캔 · 파서 (`api/_events.ts`, 순수 함수)

**입력** 채널마다 `playlistItems?playlistId=UU<채널ID 뒤>&maxResults=10` 의 `snippet`
(title, description, publishedAt, resourceId.videoId, channelTitle). 이미 시트에 있는 videoId는 건너뜀.

**이벤트 판정** 제목+설명에 `이벤트|증정|추첨|경품|나눔|드립니다|드려요|선물` 중 하나 **그리고** `구독|댓글` 중 하나.
둘 다 있어야 통과. 오탐보다 미탐이 싸므로 좁게 시작하고 시트에 쌓인 사례로 넓힌다.

**날짜 추출** 설명에서 `9월 30일`, `9/30`, `9.30`, `2026-09-30` 꼴을 전부 찾는다(연도 없으면 게시 연도, 게시일보다
앞서면 다음 해). 게시일 이상, 게시일+90일 이하만 후보.
- 발표일: 앞 15자 또는 뒤 10자에 `발표|추첨|당첨` 이 붙은 첫 후보
- 마감: 앞 15자 또는 뒤 6자에 `까지|마감` 이 붙은 첫 후보 → 없으면 `~`/`-` 범위의 뒤쪽 날짜 → 없으면 발표일 아닌 후보 중 가장 이른 것
- 못 찾으면 마감 = 게시일+7, 발표 = 마감+7, `guessed=true` (시트엔 날짜 뒤에 `?`)

**발췌** 설명을 빈 줄로 나눠 이벤트 키워드가 있는 첫 문단. `|`·줄바꿈 제거, 300자.

## 2. 데이터 (건강 데이터 스프레드시트 탭 2개, GAS 수정 없음)

GAS `action=health&type=<탭>` 이 아무 탭에나 `start|end|value|extra` 를 붙이고 `healthRows?type=<탭>` 으로 읽는다.
그 틀을 그대로 쓴다. **수정 없이 추가만** — 현재 상태 = videoId별 마지막 행. 언제 지원·확인했는지가 공짜로 남는다.

`events` 탭

| start | end | value | extra |
|---|---|---|---|
| 기록 시각 | videoId | `new` | `채널명\|제목\|마감\|발표\|발췌` (마감·발표는 `YYYY-MM-DD`, 추정이면 뒤에 `?`) |
| 기록 시각 | videoId | `reminded` | (빈칸) |
| 기록 시각 | videoId | `applied` `won` `lost` `skipped` | 메모 |

`event_channels` 탭: `추가 시각 | 채널ID | 채널명 | 핸들`. 빼려면 시트에서 행 삭제.

읽기: events 120일, channels 3650일. 둘을 `Promise.all` 로 동시에(GAS 호출은 각 10초라 직렬이면 20초).
마감 지난 `new`/`reminded` 는 조회 때 **놓침**으로 표시만 하고 행은 안 만든다.

## 3. API · 트리거 · 단축어

**`api/events.ts`** GET, `?t=<SYNC_TOKEN>` (`/api/today` 와 같은 통로)
1. 시트 읽기(채널·이벤트)
2. `YOUTUBE_API_KEY` 있으면 채널마다 스캔 → 없던 videoId를 `new` 로 저장. 채널 하나 실패는 건너뛰고 `errors` 에 이름만
3. 상태 `new` 전부에 `reminded` 행 추가, 마감이 오늘 이후인 것만 JSON `events` 로 반환
4. `&peek=1` 이면 3에서 저장 안 함. `&format=text` 면 사람이 읽는 텍스트

응답: `{ events: [{ id, channel, title, url, deadline, announce, guessed, remindAt, announceAt, excerpt }], scanned, added, errors }`
`remindAt` = 마감 전날 09:00 KST ISO, `announceAt` = 발표일 09:00 KST ISO. 단축어가 그대로 날짜로 쓴다.

**cron 없음.** 스캔과 큐를 한 요청에서 하고 트리거는 단축어 자동화 하나. 하루 빠져도 다음 날 최근 10개를 다시 본다.

**단축어 `eventsync`** (`gas/build_event_shortcut.py`, 헬퍼는 `gas/shortcut_lib.py` 로 빼서 건강 생성기와 공유)
```
URL 내용 가져오기 → 사전 값(events) → 반복:
  미리알림 추가 "[지원] 채널 · 제목"  알림 remindAt,   메모 url + 발췌,  목록 "이벤트"
  미리알림 추가 "[결과] 채널 · 제목"  알림 announceAt, 메모 url
  알림 표시 "새 이벤트: 채널 · 제목"
```
이벤트 0건이면 반복이 안 돌아 조용하다(조건문 없이). 자동화: 시각 09:00 → `eventsync`. 미리알림 목록 `이벤트` 는 미리 만든다.

## 4. MCP 툴 2개 (`api/mcp.ts`)

**`event_list`** (인자 없음) — 시트 읽고, 키가 있으면 스캔도 한다(단축어가 아직 없어도 동작). `reminded` 는 안 찍는다.
출력 4묶음: 지원 대기(마감순, 링크·발췌 포함) / 지원함(발표 대기) / 결과(최근 30일) / 놓침. 댓글 초안은 클로드 앱이 발췌를 보고 그 자리에서 쓴다.

**`event_log`** (`text` 필수) — 한 줄 문법
```
지원 <키워드> [메모]          → applied
당첨 <키워드> [경품·메모]      → won
탈락 <키워드>                 → lost
패스 <키워드>                 → skipped
채널 추가 <@핸들 | 채널 URL>   → channels?forHandle= 또는 id= 로 확인 후 event_channels 에 추가
이벤트 추가 <영상 URL> [마감 MM-DD] [발표 MM-DD] → videos?id= 로 snippet 받아 파서 통과, 날짜는 준 것이 우선
```
키워드는 활성 이벤트(new·reminded·applied)의 채널명·제목 부분 문자열, 대소문자 무시. 0건이면 목록을 돌려주고, 2건 이상이면 후보를 보여주고 저장 안 함.

서버 `instructions` 에 한 문장 추가: 이벤트 질문·기록은 `event_*`.

## 환경변수

`YOUTUBE_API_KEY` (Vercel, 서버 전용). 없으면 스캔만 건너뛰고 나머지는 동작.
