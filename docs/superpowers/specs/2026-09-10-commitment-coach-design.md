# 약속 코치 (삶 전반 코치 1단계)

2026-09-10

## 문제

건강은 코치가 있는데 그 밖의 삶은 기록이 없다. 지금 스케줄은 클로드 앱 프로젝트("핀보드")에
적어두고 손으로 캘린더·미리알림에 옮긴다. 핀보드는 프롬프트 기반이라 **상태가 없다** —
어제 뭘 넣었는지, 그중 뭘 했는지 서버가 되짚지 못한다. 그래서 코치가 아니라 매번 처음부터
조언하는 챗봇이 된다.

목표는 "삶 전반 코치"지만 그건 최소 네 조각이다(약속 이행 · 돈 · 구직 · 통합 리뷰).
아래 셋은 전부 첫 번째 위에 서므로 **1단계는 약속 이행 하나만** 짓는다.

## 근거

**사용자 자신의 데이터가 제일 강한 증거다.** 2026-08-26 ~ 09-09 계획 이행을 종목별로 가르면:

| 종목 | 이행 | 트리거 |
|---|---|---|
| 수영 | 4번 계획 → 4번 다 함 | 월수금 09:00 드림파크, 외부 강습 |
| 턱걸이 | 4번 계획 → 0번 | "수영 끝나고" (장소·시각 미정) |

같은 사람, 같은 2주, 같은 계획표. 차이는 **언제 어디서가 정해져 있느냐**뿐이다.

문헌도 같은 말을 한다.

- **if-then 계획은 이행을 2~3배 올린다** (94개 연구 메타분석, d=0.65). 독감 예방접종 실험에서
  대조군 33% vs 직접 if-then을 쓴 집단 72%.
- **시스템이 버려지는 1위 원인은 설치 마찰.** 대부분 효과를 보기 전에 설치 단계에서 포기한다.
  → 새 앱·새 화면·새 습관을 만들지 않는다.
- **2위는 과부하.** 진짜 의도와 무관한 항목이 쌓이면 정리 자체가 일이 되고, 6개월째 이월되는
  항목이 생기면 시스템을 버린다.
- **대부분 목표는 하나만 잡는다(79%)**, 목표를 늘리면 goal dilution 이 생긴다.

## 설계 원칙

1. **트리거 없는 항목은 등록 거부.** "언젠가 할 일"을 받는 순간 핀보드가 된다.
   `parseLog` 가 컨디션에 1~5 범위를 강제하듯 트리거를 강제하고, 없으면 에러를 뱉는다.
2. **새 입력 통로를 만들지 않는다.** 클로드 앱에 한 줄 던지는 `health_log` 가 이미 돌아간다.
   거기 종류 하나를 추가한다. 설치 마찰 0.
3. **동시 활성 5개 상한.** 사용자 데이터가 9~11개는 너무 많다고 말한다(2주 6/19).
4. **자동 이월 금지.** 날짜가 지난 약속은 미이행으로 확정되고 사라진다. 되살리려면 다시 넣는다.
   문헌이 말하는 "유익한 마찰"이 이 지점이다. (요일형이 매주 다시 발생하는 것은 이월이 아니라
   반복 약속의 정의다 — 지난주에 못 한 것이 이번 주로 넘어오는 게 아니라 이번 주 몫이 새로 생긴다.)
5. **제안은 도메인당 하나.** 주간 리뷰가 건강 하나 + 삶 하나를 낸다. 둘까지는 지켜진다.

## 경계 — 계획과 약속은 겹치지 않는다

설계 중에 발견한 것. `계획 월 수영 턱걸이` 가 이미 운동 연쇄를 담당하므로,
약속에 "수영후 턱걸이" 같은 형태를 허용하면 **같은 항목이 두 곳에 산다.**

| | 담당 | 이행 판정 |
|---|---|---|
| **계획** (기존) | 운동 종목 | 워치 워크아웃 · sRPE 로 **자동** |
| **약속** (신규) | 운동이 아닌 것 — 지원서·서류·연락·병원 | `했다` 한 줄로 **수동** |

약속의 트리거에서 "종목후" 형태를 빼는 이유가 이것이다. 운동은 계획이 하고, 약속은 그 외를 한다.

## 데이터 모델

기존 `manual` 탭에 종류 두 개를 추가한다. 새 탭도, 새 시트도 만들지 않는다.

```
kind=약속   extra = 트리거|할 것
kind=이행   extra = 키워드
```

`HealthRow = { start, end, value, extra? }` 는 그대로다. 저장 경로도 기존
`gasPost({ action:'health', type:'manual', rows: [stamp, stamp, kind, extra].join('|') })` 를 쓴다.

## 문법

```
약속 <트리거> <할 것>
했다 <키워드>
```

트리거는 **두 가지만** 받는다. 둘 다 "언제"를 담고 있다.

| 형태 | 예 | 의미 |
|---|---|---|
| `MM-DD` | `약속 09-13 카제나 QA 제출` | 특정 날짜, 일회성 |
| 요일[시간대] | `약속 화아침 지원서 3곳` | 매주 반복. 시간대는 아침·점심·저녁·밤 (생략 가능) |

그 외는 에러:
`약속은 "약속 09-13 치과" 또는 "약속 화아침 지원서" 형식이에요. 언제 할지가 없으면 등록되지 않습니다.`

`했다` 는 부분 문자열로 매칭한다 (`했다 카제나` → "카제나 QA 제출" 이행 처리).
여러 개가 걸리면 가장 최근 것 하나만 닫는다.

## 이행 판정과 만료

- **날짜형**: 그 날짜에 이행 기록이 있으면 완료. 날짜가 지나면 **만료**(미이행으로 확정, 이월 없음).
- **요일형**: 그 주(월~일)에 이행 기록이 있으면 완료. 주가 바뀌면 새로 시작한다.
- **활성 개수** = 아직 만료 안 된 날짜형 + 요일형 전부. 6개째를 넣으려 하면 저장 대신
  현재 목록을 돌려주고 무엇을 뺄지 묻는다.

## 주기별 표면

기존 역할 분리(일간=심판 · 주간=분석가 · 월간=전략가)를 그대로 늘린다.

- **일간** (`health_today`) — 오늘 트리거가 걸린 약속만 준비도 뒤에 붙는다. 없으면 아무 말 안 한다.
- **주간** (`coach_week`) — 이행률과 **삶 제안 하나**가 기존 건강 제안 옆에 선다.
- **월간** (`coach_month`) — 이번 단계에서는 건드리지 않는다. 2·3단계(돈·구직)가 붙을 자리.

### 삶 제안 후보

`nextChange` 와 같은 방식으로 **우선순위대로 검사해 처음 걸리는 하나만** 고른다.

1. `deadline` — 3일 안에 날짜형 약속이 있다 → "이것부터"
2. `backlog` — 지난주 이행률 0.5 미만 → "새 약속 그만 넣고 밀린 것부터"
3. `overflow` — 활성이 5개다 → "하나 지우고 시작"
4. `stale` — 요일형 약속 하나가 2주 연속 미이행이다 → "버리거나 더 작게 쪼개라"
   (날짜형은 지나면 만료되므로 여기 걸리지 않는다)
5. `hold` — 지금 상태 유지

제안은 기존 `코치` 행에 저장한다(`extra = 주기|변경키|지표|목표|제안문`).
`horizon` 에 `주간` 을 그대로 쓰고 변경키로 건강 제안과 구분한다. 새 저장 형식을 만들지 않는다.

## 함정

- **`health_log` 의 `inputSchema` 는 바뀌지 않는다.** 새 문법은 설명 문자열에만 붙으므로
  `tools.lock.json` 의 properties 가 그대로고 **커넥터 재추가가 필요 없다.**
  단 `api/_mcp-tools.test.ts` 가 핸들러의 args 사용·required·설명 언급을 대조하므로
  설명에 새 형식을 빠뜨리면 테스트가 잡는다.
- `api/` 의 새 `.ts` 는 전부 서버리스 함수로 잡힌다. 테스트는 `_` 접두어.
- `Array.prototype.at` 금지 (Vercel 기본 lib 타깃).
- 트리거의 요일 파싱은 기존 `DAYS = ['일','월',...]` 를 재사용한다. 새 요일 표를 만들지 않는다.

## 범위 밖 (다음 단계)

- 2단계: 돈 코치 — 브리지 수입 목표 대비 진행, 예산 초과 경보
- 3단계: 구직 코치 — 지원 마감·인터뷰 추적 (노션 지원 로그가 원본, 여기로 복제하지 않는다)
- 캘린더·미리알림 자동 배포 — 사용자가 명시적으로 뺐다. 뿌리는 것은 지금대로 손으로 한다.
