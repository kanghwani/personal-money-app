# 가계부 코치: 먼저 알려주고 조언하기

작성일: 2026-10-11

## 목적

가계부 웹앱을 "열어서 표를 보는 곳"에서 "먼저 챙겨 주는 코치"로 바꾼다.
카드 혜택을 놓치지 않게 하고, 카테고리별로 많이 썼는지·여유가 있는지 알려 줘서 스스로 조절할 수 있게 한다.

계산은 이미 대부분 있다(`cardGlance`·`tierStatus`·`unusedBenefits`·`missedBenefits`·`splitBreakdown`).
빠진 것은 **먼저 말을 거는 방식**, **우선순위가 매겨진 조언 문장**, **때를 맞추는 것**이다.

## 핵심 결정 (브레인스토밍 승인)

- **전달은 둘 다**: 앱을 열면 홈 맨 위에서 먼저 보여 주고, 때를 놓치면 손해인 것만 폰 미리알림으로도 보낸다.
- **알림 빈도**: 정해진 날에만, 하루 최대 1개. 같은 날 여러 개면 하나로 묶는다.
- **판단 함수 하나를 앱과 서버가 공유**(A안). 파이썬 재구현(B안)·웹 푸시(C안)는 하지 않는다.
  규칙이 두 벌이 되거나, 움직이는 부품이 늘어난다.
- **카테고리 기준선은 계산값**: 정해진 예산 없음. 끝난 최근 3개월 실지출의 **중앙값**. 저장하지 않고 원장에서 매번 계산한다
  (끝난 달은 바뀌지 않으므로 "매달 갱신해 보관"과 결과가 같고, 지난 거래를 고쳐도 어긋나지 않는다).
  전달 하나만 쓰지 않는 이유: 식비 2026-09 가 73만이라 10월 기준이 튀어 "여유"만 말하게 된다.
- **맥 작업 시각**: 맥은 `pmset repeat wake MTWRFSU 07:25:00` 로 매일 깬다. 기존 launchd 작업(eventsync)을
  07:27 과 09:00 에 돌린다. 07:27 에는 코치만, 09:00 에는 이벤트와 코치 둘 다.

## 조언 종류

| 종류 | 홈에 뜨는 조건 | 미리알림 보내는 날 | 문장 예 |
|---|---|---|---|
| 실적 부족 | 다음 달 혜택이 0원이 될 보유 카드(첫 구간 미달) | 말일 5일 전, 2일 전 | 하나카드 실적 21만/30만. 이달 안에 9만 더 쓰면 11월 할인 1.5만 |
| 다음 구간 근접 | 첫 구간은 넘었고 다음 구간까지 5만 이하 | 없음 | 하나카드 4만만 더 쓰면 할인한도 1.5만 → 3만 |
| 남은 혜택 | 이번 달 안 쓴 혜택 한도가 있음 | 말일 3일 전, 남은 합계 1만 이상 | 스타벅스는 NH카드로. 50% 할인 1만원 남음 |
| 놓친 혜택 | 다른 보유 카드였으면 이번 달 3천원 이상 더 받았음 | 없음(지나간 일) | 쿠팡은 국민카드로. 이번 달 4,200원 놓침 |
| 분담금 | 안 받은 지 30일 넘은 건이 있음 | 매월 1일 | 여친 3건 12만원, 가장 오래된 건 9/2 |
| 카테고리 | 아래 "카테고리 코치" 판정 | 매월 15일(많이 씀 묶음), 한 달치를 처음 넘은 날 | 아래 표 |
| 기록 빠짐 | 미분류 거래가 있음, 또는 끝난 달 부수입 0건 | 매월 3일(부수입만) | 9월 부수입 0건. 배민·쿠팡이츠 정산 넣었어요? |

- **가족 합산 카드(`familyPooled`, 국민카드)는 매달 첫 구간(30만, 월 1만) 충족으로 간주한다.** 가족 실적이 원장에 없기 때문이다.
  기존 `benefitBalances` 가 이미 이렇게 계산하므로(잠김 없음, 최저 구간 한도) 코드 변경은 없다(2026-10-11 사용자 확인).
  실적 부족·다음 구간 조언은 내지 않고, 남은 혜택·놓친 혜택은 월 1만 한도로 낸다.

### 카테고리 코치

- **대상**: 변동지출(`fixedType !== 'fixed'`) 카테고리. 저축·대출 상환·비지출(`isSaving`·`isLoanRepay`·`isNonSpend`)은 뺀다.
  기준선이 5만 미만인 카테고리도 뺀다.
- **실지출**: `amount - split`(분담금 제외).
- **기준선**: 이번 달을 뺀, 끝난 최근 3개월 카테고리 실지출의 중앙값. 기록이 3개월 미만이면 있는 달만으로 중앙값.
- **날짜 기준**: `기준선 × 오늘 / 말일`. 7일 전에는 판정하지 않는다(월초 노이즈).

| 판정 | 조건 | 문장 예 |
|---|---|---|
| 한 달치 넘음 | 쓴 돈 ≥ 기준선 | 외식비 평소 한 달치를 넘었어요. 36만 / 평소 34만 |
| 많이 씀 | 쓴 돈 ≥ 날짜 기준 × 1.2, 그리고 차이 ≥ 3만 | 외식비 많이 썼어요. 지금 22만, 이 속도면 월말 41만(평소 34만). 남은 19일은 하루 6천원이면 평소대로 |
| 여유 | 15일 이후, 쓴 돈 ≤ 날짜 기준 × 0.7 | 외식비 여유 있어요. 남은 14일 동안 12만까지 괜찮아요. 맛있는 거 드세요 |
| 보통 | 그 외 | (조언 없음) |

- "한 달치를 처음 넘은 날"은 저장 없이 판정한다: 어제까지 누적 < 기준선 ≤ 오늘까지 누적.

## 우선순위 (홈)

마감이 가까운 것(마감일 오름차순) → 금액이 큰 것 순. 상위 3개만 보이고 나머지는 "더 보기 N건"으로 그 자리에서 펼친다.

## 컴포넌트 설계

### 1. 판단 — `src/coach.ts` (새 파일, 순수 함수)

`dashboardLogic.ts` 가 이미 967줄이라 분리한다. 기존 함수를 부르기만 하고 다시 구현하지 않는다.

- `type Advice = { id: string; kind: AdviceKind; title: string; detail: string; badge?: string; due?: string; amount: number; target?: 'insights' | 'uncategorized' }`
  - `id` 는 종류+대상(예: `tier:하나카드`, `cat:외식비`). `due` 는 `YYYY-MM-DD`, `badge` 는 "D-5" 또는 "1만 남음".
- `categoryBaselines(transactions, yearMonth): Map<string, { baseline: number; lastMonth: number }>`
- `categoryVerdict(spent, baseline, day, days): 'over' | 'heavy' | 'room' | 'ok'` — **사용자가 직접 작성(TODO(human))**, 테스트는 먼저 만든다.
- `coachAdvice(transactions, fixedDefs, today): Advice[]` — 할부 보정은 `withInstallmentCharges` 를 거친 행으로 계산(혜택 보드와 같은 `cardRows`). 정렬까지 해서 돌려준다.
- `alertFor(transactions, fixedDefs, today): { title: string; body: string } | null`
  - 위 "미리알림 보내는 날" 규칙에 해당하는 조언만 골라 묶는다. 제목은 `[가계부] MM/DD <첫 항목>` + 여러 개면 ` 외 N건`.
  - 날짜는 전부 KST `YYYY-MM-DD` 문자열로 다룬다.

### 2. 서버 — `api/coach.ts` (새 서버리스 함수)

- `GET /api/coach?t=<SYNC_TOKEN>[&date=YYYY-MM-DD]` → `{ date, alert, advice }`.
  `date` 는 실데이터로 특정 날의 알림을 미리 확인하는 용도(읽기 전용). 없으면 KST 오늘.
- 원장(`ledger`)과 고정비(`fixedList`)를 `gasGet` 으로 **동시에** 읽는다. 하나라도 실패하면 500 과 원인 문장(조언 없음).
  고정비가 빠지면 할부가 실적에서 빠져 틀린 "실적 부족" 이 나오기 때문.
- `vercel.json` 에 `maxDuration: 60`(GAS 호출 1회 10초 이상).
- `src/dashboardLogic.ts` 의 `import ... from '../api/_ledger'` 를 `'../api/_ledger.js'` 로 바꾼다(서버 Node ESM 은 확장자 필수).
  2026-10-11 스파이크: nodenext 타입체크 통과, `dashboardLogic.test.ts` 117개 통과. 앱 `vite build` 는 구현 때 확인.

### 3. 앱 — `src/App.tsx`

- 홈 맨 위(카드 혜택 보드 위)에 `CoachCard`. 한 줄 = 아이콘 · 굵은 제목 · 설명 한 줄 · 오른쪽 배지(마감 또는 금액 하나).
- 누르면: 실적·혜택 → 인사이트 탭(`onOpenInsights`), 미분류 → 카테고리 상세 시트를 미분류로. 나머지는 동작 없음.
- 상태: 혜택 보드와 같은 `benefitDataStatus`. 불러오는 중 → 회색 줄, 오류 → "원장을 못 읽어 조언을 못 냄" 한 줄. 조언 0개 → "지금 챙길 것 없음".
- 지출 도넛 아래 카테고리 순위 줄에 "평소 34만" 을 작게 붙이고, 많이 씀·넘음은 빨강, 여유는 초록.
- 카드 혜택 보드의 "놓친 혜택 N원" 줄은 코치 카드로 옮기고 보드에서는 뺀다(같은 말 두 번 안 함).
- 문구는 `src/i18n.ts` 에 추가.

### 4. 맥 — `scripts/eventsync.py` · `com.hwan.eventsync.plist`

- plist `StartCalendarInterval` 을 `[07:27, 09:00]` 배열로. launchd 는 잠든 동안 놓친 예약을 다음 기상 때 실행한다.
- 스크립트: 09시 전이면 코치만, 이후면 이벤트 → 코치. 두 단계는 서로의 실패에 영향받지 않는다(실패 시 `코치 실패: 원인` 로그).
- 코치 단계: `/api/coach` 의 `alert` 가 있으면 미리알림 **"가계부"** 목록(없으면 생성)에 하나 만든다.
  같은 `[가계부] MM/DD` 로 시작하는 미리알림이 이미 있으면 만들지 않는다(하루 1개 보장, 로그인 실행 포함).
  알림 시각은 09:00, 이미 지났으면 지금 + 1분. 울리는 건 iCloud 로 동기화된 폰이 한다.
- 07:27 은 맥이 잠겨 있어 미리알림 생성이 시간 초과(-1712)로 실패할 수 있다(2026-10-01~02 로그). 코치 서버는 상태가 없어
  09:00 실행이 같은 알림을 다시 받아 만들면 되므로 손실이 없다. 이벤트는 서버가 넘길 때 상태를 바꾸므로 09:00 에만 둔다.

## 테스트 — `src/coach.test.ts` (날짜 고정 순수 함수)

- 알림 날짜: 30일·31일·2월(평년·윤년) 말에서 D-5·D-2, 말일-3, 1일, 3일, 15일.
- 묶음: 같은 날 두 개 → `외 1건`, 해당 없음 → `null`.
- 기준선: 끝난 3개월 중앙값, 이번 달 제외, 분담금 제외, 5만 미만 제외, 기록이 1~2개월뿐인 경우.
- 판정(`categoryVerdict`): 6일 → `ok`, 여유는 15일부터, 1.2 배·3만·0.7 배 경계 위아래, 기준선 이상 → `over`.
- 한 달치 처음 넘은 날: 어제 누적 < 기준 ≤ 오늘 누적일 때만 알림.
- 우선순위: 마감 가까운 것 → 금액 큰 것.
- 가족 합산 카드: 실적이 0원이어도 실적 부족·다음 구간 조언이 없다.
- KST: `api/coach.ts` 의 오늘 계산이 UTC 15:30(= KST 00:30)에 다음 날을 내는지.

## 하지 않는 것 (YAGNI)

- 항목별 "오늘은 그만 보기" — 조언은 조건이 풀리면 저절로 사라진다. 써 보고 거슬리면 추가.
- 기준선 저장·수동 예산 입력 — 계산값으로 충분. 필요해지면 그때 덮어쓰기용 목표를 추가.
- 웹 푸시·iOS 단축어 알림 — 맥 미리알림으로 충분.
- 미보유 카드 비교 — `missedBenefits` 의 후보 카드 기능은 쓰지 않는다(보유 카드만).

4. 앱 홈을 미리보기로 열어 코치 카드·카테고리 기준선 표시 확인.
