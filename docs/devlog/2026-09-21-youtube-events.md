# 2026-09-21 유튜브 구독자 이벤트

## 왜 이렇게

- **RSS 를 버렸다.** 설계 전에 대상 채널 피드를 직접 쳐보니 십만양품·디에디트·기즈모 404, ITSub 500, UNDERkg·침착맨 200.
  채널 페이지가 `feeds/videos.xml?channel_id=` 링크를 광고하는데도 404 다. 원인은 못 찾았고 채널마다 달라서 소스로 못 쓴다.
  Data API 는 키만 있으면 되고 `playlistItems` 가 설명 전문을 준다(1단위/호출). 설계 첫 섹션 전에 확인해서 다행이었다.
- **GAS 를 안 건드렸다.** `action=health&type=<탭>` 이 아무 탭에나 `start|end|value|extra` 를 붙인다.
  `events` 탭에 상태 변화를 행으로 추가만 하고 마지막 행이 현재 상태. 수정 API 를 만들 필요가 없고 이력이 공짜다.
- **cron 없음.** 단축어가 `/api/events` 를 부르면 서버가 스캔·큐를 한 번에 한다. 트리거가 하나면 고장 지점도 하나.
  하루 빠져도 다음 날 최근 10개를 다시 보므로 잃는 게 없다.
- **미리알림 두 개.** 마감 전날 "[지원]", 발표일 "[결과]". 알림은 미리알림 앱이 담당하고 서버는 날짜만 준다.
  0건이면 반복이 안 돌아 조용하다 — 단축어 조건문은 변수 비교가 자주 깨져서 안 쓴다(건강 생성기의 교훈).
- **댓글은 손으로.** 자동 댓글은 계정 위험. 발췌를 `event_list` 가 돌려주면 클로드 앱이 그 자리에서 초안을 쓴다.
- **가계부는 인프라만.** 당첨금은 필요할 때 `ledger_add` 로. 코드 0.

## 헛디딘 곳

- 이벤트 키워드에 `드립니다|드려요` 를 넣었더니 "구독과 좋아요 부탁드려요" 가 이벤트로 잡혔다. 뺐다.
- 발표일 판정에서 "9월 28일\n당첨자 발표: 9월 30일" 의 28일이 다음 줄 "당첨" 을 끌어와 발표일로 찍혔다.
  앞뒤 창을 같은 줄로 제한했다.
- YouTube 검색 결과 HTML 의 `"channelId"` 는 엉뚱한 채널을 준다. 채널 페이지의 `"externalId"` 가 맞다.

## 오후: 검색 기반으로 바꿈

- 감시 채널 4개로 첫 스캔 → 3건, 전부 지난 것. "채널을 훨씬 늘려야 유의미하다"는 사용자 말이 맞았다.
  채널을 손으로 모으는 대신 **하루 한 번 검색**("댓글 이벤트"·"구독자 이벤트", 최근 7일)으로 이벤트를 직접 찾는다.
  소규모 채널이 자동으로 섞이고, 댓글 수·구독자 수를 같이 저장해 "지원 대기"를 댓글 적은 순으로 놓는다.
- **첫 실검색 95건 중 77건이 잡음.** 구독 2명 채널의 소원 댓글, 원석 판매 라이브, 로블록스 친추 이벤트가
  "댓글 0"이라 맨 위에 왔다. 검색으로 온 것만 경품 언급·라이브 제외·결과 영상 제외·구독자 1천 이상으로 걸렀더니 12건.
  그중 네이쳐필름(댓글 0·구독 1.1만), 이마트24(상품권 5명·댓글 27), 진이어트(10명·댓글 45)처럼 확률 좋은 게 보였다.
- 이미 시트에 들어간 잡음은 `skipped` 무덤돌 83행으로 덮었다. 추가 전용이라 지우는 대신 덮는다.
- `@theedit` 은 빈 채널이었다. 검색 결과 HTML 의 `channelId` 는 못 믿고 채널 페이지 `externalId` 만 믿을 것.
- 사용자는 폰 안 쓰고 맥에서만 쓸 예정 → 단축어 설치 안 함. 클로드 데스크톱 앱의 `event_list` 가 스캔까지 하므로 그걸로 충분.

## 남은 것

- 매일 알림이 필요해지면 맥 launchd + `shortcuts run eventsync`(맥 단축어 앱에 같은 파일 설치). 지금은 안 함.
- 천주교 수원교구·공동구매 같은 잡음이 아직 있다. 사례 쌓이면 PRIZE_RE·제외어를 조인다.
- 판정 규칙은 좁게 시작했다. 놓친 이벤트가 보이면 `EVENT_RE` 를 넓힌다.
