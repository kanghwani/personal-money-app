# 2026-10-11 ~ 10-12 · 가계부 코치

설계: `docs/superpowers/specs/2026-10-11-money-coach-design.md`, 계획: `docs/superpowers/plans/2026-10-11-money-coach.md`.
앱이 먼저 말을 건다. 홈 맨 위 "오늘의 코치"와, 정해진 날 하루 1개 맥 미리알림.

## 결정과 근거

- **계산은 이미 있었다.** 실적·남은 혜택·놓친 혜택·분담금은 `dashboardLogic.ts` 에 다 있었고 빠진 건 "먼저 말하기·우선순위·때"였다.
  그래서 `src/coach.ts` 는 기존 함수를 부르기만 하고 다시 구현하지 않는다. 가족 합산 카드(국민) 예외도 그 덕에 공짜로 따라왔다.
- **판단 하나를 앱과 서버가 공유.** 파이썬으로 알림 규칙을 따로 짜면 앱과 알림이 다른 숫자를 말하게 된다.
  서버가 `src/` 를 import 하려면 상대 경로에 `.js` 확장자가 필요했다(Node ESM). Vite·Vitest 는 `.js` 를 `.ts` 로 풀어 줘서 앱은 그대로.
- **카테고리 기준선은 저장하지 않는다.** 끝난 최근 3개월 중앙값을 매번 계산한다. 끝난 달은 안 바뀌니 "매달 갱신해 보관"과 같고,
  지난 거래를 고쳐도 어긋나지 않는다. 전달 하나만 쓰면 식비 9월 73만 같은 달에 끌려 "여유"만 말하게 된다.
- **국민카드는 매달 첫 구간(30만, 월 1만) 충족으로 간주**(사용자 확인). 가족 지출이 원장에 없어 판정할 수 없다. 기존 혜택 보드와 같은 가정.
- **알림은 기간이 아니라 날짜.** "말일 5일 전부터"면 5일 연속 같은 알림이 온다. D-5·D-2, 말일-3, 1일, 3일, 15일로 콕 집었다.
- **맥은 pmset 으로 07:25 에 깬다.** launchd 를 07:27·09:00 에 돌린다. 07:27 에는 코치만 — 코치 서버는 상태가 없어 잠긴 맥에서
  미리알림이 실패해도 09:00 이 같은 알림을 다시 만들면 되지만, 이벤트 서버는 넘길 때 상태를 바꾸므로 09:00 에만 둔다.
  미리알림 알림 시각은 09:00 — 울리는 건 iCloud 로 받은 폰이라 맥이 그때 자고 있어도 된다.

## 헛디딘 곳

- **"한 달치를 처음 넘은 날" 알림이 실제로는 영영 안 올 뻔했다.** 규칙은 "어제 누적 < 기준 ≤ 오늘 누적"이었는데, 맥은 아침에만 돌고
  넘게 만든 지출은 전날 저녁에 입력된다 → 아침엔 어제·오늘 누적이 같다. 테스트는 날짜만 넣어 통과했다. 최종 검토(새 컨텍스트)가 잡았다.
  이제 "어제 넘었나"를 다음 날 아침에 본다. **시간에 따라 도는 기능은 실제 실행 시각으로 테스트해야 한다.**
- **같은 이유로 월초 판정이 알림과 엇갈렸다.** 6일에 폰은 "한 달치 넘음"인데 홈은 "챙길 것 없음". 넘음은 추정이 아니라 사실이라 월초에도 판정한다.
- **미리알림 중복 검사에 연도가 없었다.** 완료한 미리알림도 이름 목록에 남아서 내년 같은 날짜가 막혔을 것이다. 마감일 날짜까지 비교한다.
- **0.7배 경계에서 부동소수점.** 170000 × 0.7 = 118999.999… 라 119,000 이 "여유"에서 빠졌다. 양변을 곱해 정수로 비교한다.
- **테스트가 실패했는데 커밋됐다.** `vitest | grep` 파이프가 종료 코드를 삼켰다. 로그 파일로 돌리고 종료 코드를 본 뒤 커밋한다.
- **"통합 할인 50%".** 통합 한도 카드의 rate 는 영역 중 최대값이라 전 영역 50% 로 읽혔다. 한도만 보인다.
- **eslint 가 `.superpowers/` 의 임시 `.ts` 를 읽는다.** 작업 공간에 코드 조각을 `.ts` 로 두면 린트 오류가 늘어 보인다.
- **`vercel --prod` 첫 시도 "Not authorized"** 가 또 나왔다(10-10 에 이어 두 번째). 바로 다시 하면 된다. 배포 결과의 status 를 먼저 보고 다음 단계로.
- **10-12 09:00 이벤트 동기화가 `/api/events` 응답 시간 초과로 통째로 죽었다**(로그 한 줄 없이). 이제 이벤트 단계 실패는
  `이벤트 실패:` 한 줄로 남고 코치 단계와 서로 막지 않는다. 채점 안 된 이벤트는 다음 실행에 다시 오므로 그날 것도 복구됐다.
