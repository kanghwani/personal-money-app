# 가계부 조회·점검

구글시트 원장을 조회·수정한다. 폰에서 한 줄로 말해도 처리되는 게 목적.

## 실행

작업 디렉터리 무관, 아래 스크립트를 그대로 실행한다.

```bash
python3 /Users/hwan/dev/paused/money-app/.claude/skills/ledger/ledger.py <명령>
```

| 요청 예시 | 명령 |
|---|---|
| "가계부 점검", "이상한 거 있어?" | `check` |
| "이번 달 얼마 썼어", "7월 어땠어" | `month` / `month 2026-07` |
| "코스트코 얼마 썼지" | `find 코스트코` |
| "식비 얼마야" | `cat 식비` |
| "하나카드 내역" | `card 하나카드` |
| "여친한테 얼마 받아야 해", "분담금 다 받았어?" | `split` |
| "고정비 뭐 있지" | `fixed` |
| "현대카드 내역 대조해줘"(이용내역 붙여넣음) | 붙여넣은 걸 파일로 저장 → `recon 현대카드 <이용내역> [형장부] owner=김강환 prepaid=<선결제액>` |

기본값은 `check`. 인자 없이 실행하면 점검 + 이번 달 요약을 낸다.

### 수정

| 요청 예시 | 명령 |
|---|---|
| "5000 스타벅스 하나카드 추가" | `add "5000 스타벅스 하나카드"` |
| "금액 15100으로 고쳐" | `edit <id8> amount=15100` |
| "그거 반반 처리해줘" | `half <id8>` |
| "삭제해줘" | `rm <id8>` |
| "월세 받았어", "브리가 코스트코 정산했어" | `settle 월세` / `settle 코스트코 all` |

- **`add`는 서버 빠른입력 파서를 그대로 쓴다** — 금액·결제수단·날짜(`어제`/`오늘`)·카테고리 자동, 같은 id 중복 방지. `+`를 앞에 붙이면 수입.
### 유튜브 구독자 이벤트 (경품)

| 요청 예시 | 명령 |
|---|---|
| "이벤트 뭐 있어", "지원할 거 있어", "마감 언제야" | `event` |
| "십만양품 댓글 달았어" | `event 지원 십만양품` |
| "에어프라이어 당첨됐어" | `event 당첨 십만양품 에어프라이어 15만` |
| "키보드 떨어졌어" / "이어폰은 안 할래" | `event 탈락 키보드` / `event 패스 이어폰` |
| "이 채널 봐줘" | `event 채널 추가 @핸들` (삭제는 `채널 삭제 @핸들`) |
| "이 영상 이벤트 넣어줘" | `event 이벤트 추가 https://youtu.be/xxx 마감 10-05 발표 10-07` (날짜 생략 가능) |

- `event` 목록의 지원 대기 항목은 발췌를 보고 **댓글 초안을 써 준다**(댓글은 사용자가 직접 단다).
- 마감·발표 뒤의 `?` 는 설명에서 날짜를 못 찾아 추정한 값이다. 영상에서 확인하라고 알린다.
- 키워드가 여러 건에 걸리면 서버가 후보 목록을 돌려준다. 제목 단어로 좁혀 다시 실행한다.
- **당첨되면** 경품·당첨금을 가계부에도 넣을지 묻고, 넣으면 `add "+금액 이벤트 당첨 채널명"`.

- `edit` 항목: `amount memo payment date split cat sub type fixed`
- `id8`은 조회 결과 맨 앞 8자리. **먼저 `find`/`check`로 대상을 확인한 뒤 수정한다.**
- 수정·삭제 전 **무엇을 바꾸는지 사용자에게 한 줄로 알리고 실행**한다. `rm`은 되돌릴 수 없으니 대상이 맞는지(날짜·금액·메모) 확인하고 실행한다.

## 결과 전달 방식

**스크립트 출력을 그대로 붙여넣지 말고** 핵심만 3~5줄로 요약해서 답한다.

- `check`에서 이상 항목(미분류·중복·금액0·미래날짜·결제수단없음·모호한 "카드")이 나오면 **건별로 짚고 어떻게 고칠지 제안**한다. 0건이면 "깨끗하다" 한 줄로 끝낸다.
- 금액은 천 단위 콤마, "원" 붙여서.
- 수정한 뒤에는 바뀐 값을 한 줄로 확인해준다("서브웨이 15,000 → 15,100원").
- 여러 건을 한꺼번에 고쳐야 하면(예: "8월 코스트코 전부 반반") 각 건의 id를 `find`로 뽑아 `half`/`edit`을 반복한다.

## 알아둘 것

- 인증정보는 `personal-money-app/.env`(gitignore됨)에서 읽는다. 토큰을 출력하거나 외부로 보내지 않는다.
- 백엔드가 Google Apps Script라 가끔 302/404를 뱉는다 → 스크립트가 4회까지 자동 재시도한다. 그래도 실패하면 잠시 후 다시.
- **분담금(`split`)** = 내가 결제했지만 남이 부담하는 몫(여친·형·엄마) + 자동 환급(메모에 환급/피클). 내 실지출 = 결제액 − 분담금.
- **받았는지**는 메모 끝의 `· 받음 MM-DD` 로 판단한다. `split`은 안 받은 것 전체(월 무관)와 그 달의 받을·받음·남음을 낸다. 2026-09-01 전 기록은 표시 없어도 정산된 것으로 본다.
- 월 요약의 고정비는 생활고정 / 부채상환(금융/대출 카테고리 + 메모에 할부) / 저축(저축/투자) 으로 갈라 보인다.
- **`recon`** = 카드 이용내역을 원장·형 장부와 금액 일치+날짜 ±7일로 대조. 카드에만 있는 것(내 것/형 것 질문), 원장에만 있는 것(결제수단·금액 확인), 형 장부에만 있는 것(형 장부 오타), 형 정산(장부의 내 카드·명의 결제 + 4대보험 형 몫 − 선결제)을 낸다. 형 장부는 읽기만 한다.
- **실적 제외 추정**: 관리비·4대보험·할부·보험·세금은 카드 전월실적에서 빠지는 게 일반적이라 `EXCL`로 따로 구분해둔다.
